# Rylune Launcher 0.8 — Crimson / Modern Fabric

Tauri 2 + React + Rust. The Crimson identity, logo and wallpapers are retained; the desktop layout is larger with animated navigation, cards and dialogs. Reduced-motion preferences are respected. The Home cards now feature 1.21.11, 26.2 and 26.3. The Versions tab fetches official stable releases in the 1.21.11–26.3 release families (including hotfixes); fallback cards do not imply local installation. All supported versions use official Fabric Loader, not the old OneClient-only Rylune 1.8.9 mod. Fabric API and optimization mods are not automatically installed.

## Windows setup
Install Node.js LTS, Rust stable MSVC (rustup.rs), Visual Studio Build Tools with Desktop development with C++ and a Windows SDK, and WebView2. Java is automatically provisioned if the required version is not installed. Java selection follows official Minecraft metadata, checks the exact major version, and searches JAVA_HOME, common Windows JDK locations, the official Minecraft runtime directory, the profile runtime directory and PATH. If detection fails, edit the profile and provide the full java.exe path. If no matching Java is installed, the launcher downloads the required official runtime into the selected profile. Custom Java paths remain supported.

Run `start.bat` (or `npm install` then `npm run tauri dev`). To create a Windows NSIS installer run `build.bat` or `npm run tauri build`. Output: `src-tauri/target/release/bundle/nsis/`. The repository GitHub Actions workflow builds Windows binaries and publishes the alpha release only on success.

## Game directories
On Windows, paste `%APPDATA%\Rylune\profiles` into Explorer. The initial 1.21.11 profile directory is created on load; others are created when profiles are added. Example after installing a profile:

```
%APPDATA%/Rylune/
  settings.json
  profiles/
    1.21.11/
      assets/        # objects, indexes, log_configs
      libraries/     # Minecraft and Fabric libraries
      versions/      # game JAR + version JSON and Fabric JSON
      natives/
      mods/
      config/
      saves/
      resourcepacks/
      shaderpacks/
      screenshots/
      logs/
      crash-reports/
      runtime/       # automatically provisioned Java runtime
      fabric-profile.json
      .rylune-installed.json
      options.txt    # generated by Minecraft when run
    26.2/
    26.3/
    1.21.11-<uuid>/  # additional custom profile of same version
```

Every profile is its own working directory (`--gameDir`) AND installation root, with its own assets, libraries and version files. Nothing is shared between profiles; this deliberately uses more disk space. The first profile of a version uses the exact version directory when available; additional instances use a unique ID suffix. The folder icon in Profiles opens the full game directory. Put mods in that profile's `mods` folder. Changing a profile version switches to a separate folder; old files remain. Removing a profile entry never deletes files, and recreating a canonical version profile can reuse its old directory. Back up before changing versions. Old v0.5 data under `%APPDATA%/RyluneLauncher` is left untouched and is not automatically migrated. Fresh settings and accounts are needed.

## Installation and authentication
Set your Minecraft-approved Microsoft public-client OAuth application ID in Settings (personal Microsoft accounts, public client device code flow, Minecraft API approval). Use Accounts > Microsoft to sign in and verify Java Edition ownership via the Minecraft profile endpoint. Session tokens are held in memory; sign in again after restart or expiration. No password or secret is collected. Offline profiles are for local play by Minecraft owners. Installation and repair use public official download endpoints and no Microsoft session is required; a first install needs internet. Cached complete profiles can launch without internet. Offline identities cannot join authenticated online-mode servers. Java is installed automatically when needed.

Select a version in Home, create/select its profile, then Launch, or use Install in Versions. Rust reads the official Mojang version manifest, gets the stable Fabric Loader version/profile from Fabric Meta, downloads client, libraries, assets and log config, checks SHA-1 when supplied, and writes an installation marker only after preparation. Cached Fabric metadata pins the chosen loader for that profile. Install/repair checks files, not loader upgrades. The launcher selects the appropriate Java runtime, uses a JVM argument file to reduce Windows command-line length, supplies the profile's working directory, and pipes output to Logs. The JVM argfile does not include game authentication arguments. Native/runtime compatibility and actual launch remain to be tested. Assets are downloaded sequentially; first installs may take considerable time.

## Validation and limitations
JSX syntax and JSON/TOML configuration parsing checked. CSS and wallpaper/logo assets unchanged from 0.5. Added Rust unit tests for version range and JVM argument quoting; not executed because Rust toolchain is unavailable. Windows executable, authentication, Fabric downloads, Java detection, and in-game launches have not been tested. The package is source code, not a built EXE. No proprietary OneClient binaries, Mojang game files, or modern mods are distributed.

## 0.7 changes
Installation no longer treats local identity as lack of internet. Install-only operations need no selected account; launching requires a selected local identity or valid Microsoft session. No Microsoft token is fabricated. Windows runtime and game launch must still be tested on a real installation.

## 0.8 changes
Automatic Java provisioning from Mojang's runtime manifest; retryable downloads; real Java process version check; persisted redacted game console output in logs/launcher-latest.log; launch-state reporting; simplified UI. The Windows release workflow includes live official metadata and Java argument-file smoke checks. These checks do not establish graphical Minecraft gameplay or Microsoft login success.
